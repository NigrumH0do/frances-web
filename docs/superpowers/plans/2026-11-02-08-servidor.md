# P08 Servidor — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Lee `AGENTS.md` antes de tomar una tarea.

**Goal:** Dejar Frances Classroom corriendo como servidor propio en una instancia ARM con `docker compose up -d`: API FastAPI con cuentas por invitación y CSRF, la cola de trabajos y el worker que corre el pipeline v1 a las 05:17 y los domingos 06:00 de Bogotá, endpoints de lectura del contenido que ya existe, admin del pipeline, backup diario a Object Storage de Oracle y CI que construye la imagen arm64.

**Architecture:** Paquetes nuevos `frances.api` (FastAPI), `frances.accounts` (argon2id, invitaciones, sesiones), `frances.jobs` (cola, worker, programador, handlers del pipeline) y `frances.backup`. Todos usan el `Store` v1 en modo WAL (CHG-01) y las migraciones `0002`–`0004` (CHG-02…04). Los contratos nuevos (modelos, IDs, config) entran por tareas CHG antes que el código que los consume. `infra/` trae el Dockerfile multi-stage (targets `app` y `web`), `compose.yaml` y `Caddyfile`.

**Tech Stack:** Python 3.12, FastAPI 0.162.0 (Starlette 1.10.0), Uvicorn 0.54.0, argon2-cffi 25.1.0 (bindings 26.1.0), pydantic 2.14.1, SQLite WAL + FTS5, boto3 1.40.76 (ya en el lock), Caddy 2.11.7, Docker Buildx + QEMU, pytest + `fastapi.testclient`, respx, `botocore.stub.Stubber`, PyYAML.

**Spec:** `docs/superpowers/specs/2026-11-02-frances-v2-servidor-design.md` (§3 M1–M3, §5, §7 Pipeline/Usuarios, §9, §10, §11)

Plan maestro v2: `docs/superpowers/plans/2026-11-02-00-v2-master-plan.md` (Global Constraints v2, contratos y R-31…R-45 aplican a todas las tareas). El plan maestro v1 sigue vigente.

## Restricciones del subsistema

- Las tareas CHG-xx no tienen `owns` (R-31): su bloque **Touches** es la lista exacta de archivos que pueden cambiar, además de sus tests. Un CHG actualiza contrato y consumidores en un solo PR y se fusiona antes que las SRV que lo usan.
- Toda ruta nueva vive en un módulo de `ROUTER_MODULES` con `router: APIRouter(prefix=…, dependencies=[Depends(require_user)])` (R-32, R-33); las de admin agregan `require_admin`.
- Los repos SQL de cada tarea viven en sus propios módulos (`content_repo.py`, `cards_repo.py`, `accounts/repo.py`, funciones `_q_*`). El DDL solo en migraciones.
- La API no hace red salvo `POST /api/speech/token` (Azure STS). El worker hace la red del pipeline v1. Ningún endpoint de lectura llama al LLM.
- Tests de API con `TestClient(app, base_url="https://testserver")` y las ayudas de `tests/testkit/api.py` (R-35). Tests de Docker que construyen imágenes: `@pytest.mark.heavy`.
- Tiempo inyectable: todo lo que depende de la hora recibe `now: datetime` o `ApiContext.now`; los tests usan relojes fijos en UTC.
- CLI (R-05 v1): cada comando nuevo declara `data: DataOpt = Path(".")` cuando opera sobre datos, pero dentro de los contenedores el valor por defecto lo toma de `resolve_data_dir(env, Path("."))` (CHG-07).
