# P12 Go-live — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Lee `AGENTS.md` antes de tomar una tarea.

**Goal:** Poner Frances Classroom v2 en producción sobre una instancia Oracle Cloud ARM (Ampere A1), con HTTPS automático, secretos solo en `/srv/frances/.env`, imágenes construidas de forma nativa en la instancia, datos reales solo en `/srv/frances/data`, primer backfill verificado y una aceptación firmada; después retirar el FRB1, R2 y el Worker v1 sin borrar los fixtures sintéticos que usa el demo.

**Architecture:** El `docker compose` de P08 (`caddy`, `api`, `worker`, `backup`) corre sobre `/srv/frances`. Caddy publica 80/443 TCP y 443/UDP; `api`, `worker` y `backup` comparten la imagen `frances-app:local`, no publican puertos, usan usuario `10001:10001` y `read_only`. El build es nativo `linux/arm64` en la instancia (R-45, sin registro de imágenes). El backup va a un bucket privado de OCI Object Storage por la API compatible con S3 (R-44). Google, Azure, OneRouter y las claves del backup se escriben a mano en `/srv/frances/.env`; Caddy solo recibe `/srv/frances/caddy.env`, sin secretos. Ningún workflow de GitHub Actions corre en producción: el `worker` ejecuta el pipeline, `auth.check`, `plan.daily` y el backup.

**Tech Stack:** lo de P08–P11 (Python 3.12, FastAPI 0.162.0, Uvicorn 0.54.0, SQLite WAL, Caddy 2.11.7, Docker Buildx/Compose) + Oracle Cloud Always Free (Ampere A1, aarch64), Ubuntu 24.04 LTS, Docker Engine y el plugin `docker compose`, Let's Encrypt y Object Storage de OCI compatible con S3. No hay dependencias nuevas.

**Spec:** `docs/superpowers/specs/2026-11-02-frances-v2-servidor-design.md` (§3 M1–M3 y M5, §5, §9, §10, §11, §12.1–§12.3 y §13).

Plan maestro v2: `docs/superpowers/plans/2026-11-02-00-v2-master-plan.md` (Global Constraints v2, «Layout en el servidor», «Servicios de `infra/compose.yaml`», «Variables de entorno v2», R-41, R-44, R-45 y «Tareas v1 canceladas»). El plan maestro v1 sigue vigente en lo que no se reemplaza aquí.

Manual de subagentes: `docs/superpowers/plans/2026-11-06-manual-subagentes.md` (sección 7: las decisiones del conductor ganan sobre este plan).

## Global Constraints aplicables

Heredan todas las Global Constraints v1 y v2. Para P12 son vinculantes, además:

- **Secretos.** Solo viven en `/srv/frances/.env` (permisos `600`, dueño `root`) y se leen en `frances.config`. `caddy.env` es `644`, dueño `root`, y no lleva secretos (solo dominio y correo ACME; la región de Azure Speech no hace falta desde ADR-022 porque la CSP usa el comodín `wss://*.stt.speech.microsoft.com`). Nunca se escriben en el repo, en un ADR, en un issue, en un comando copiado a la historia del shell ni en un log. Para editar: `sudoedit`; para las contraseñas: el prompt oculto de la CLI.
- **Datos reales.** El repo sigue público y solo con fixtures sintéticos. Los datos del curso viven solo en `/srv/frances/data` y en el bucket privado de backup. En ADRs, issues y logs solo se anotan fechas, ids de trabajo, conteos y rutas relativas; nunca nombres de cursos, profesores, publicaciones o archivos, ni correos completos, tokens o claves.
- **Red.** Solo `caddy` publica puertos: 80 TCP, 443 TCP y 443/UDP. `api` escucha en la red interna `edge`; `worker` y `backup` no publican nada. La Security List de Oracle y el firewall del sistema deben permitir exactamente esos puertos; SSH (22) solo desde la IP del dueño. Ningún otro puerto queda expuesto a Internet. `caddy` y `api` son los únicos servicios en `edge`; el `forwarded_allow_ips="*"` actual de `frances serve` se acepta solo por ese aislamiento. Si otro contenedor entra a `edge`, se abre un CHG para fijar el CIDR en `frances serve` y en compose.
- **ARM y build.** La instancia es `aarch64`. Las imágenes se construyen nativas en la instancia con `docker compose build`; no se publican en un registro ni se usa QEMU en producción. `scripts/check_aarch64_wheels.py` sigue siendo el guardián del lock (R-45, SRV-14).
- **Contenedores.** `api`, `worker` y `backup` corren como `10001:10001`, `read_only: true`, `tmpfs: /tmp` y `restart: unless-stopped`. Solo `caddy` monta `/srv/frances/caddy/{data,config}`; `api`, `worker` y `backup` montan `/srv/frances/data:/data`. Caddy no monta `/srv/frances/data` ni recibe `/srv/frances/.env`.
- **Backup.** `state.db` se copia con la API online de SQLite (nunca copiando el archivo con WAL abierto), se verifica con `PRAGMA integrity_check`, se comprime y se sube a OCI. La retención de 14 días la aplica `frances backup` (R-44). El bucket es privado: sin acceso público, sin URL prefirmada pública y sin lifecycle que borre la última copia.
- **Sin red en tests.** Los tests de P12 son de sistema de archivos, CLI y contenido de ADRs. Lo que necesite red o una instancia real se marca `@pytest.mark.heavy` y no corre en CI. Los tests de aceptación los ejecuta el dueño en el servidor; no se simulan resultados.
- **Sin contratos nuevos.** P12 no agrega modelos, rutas, migraciones, `JobKind` ni dependencias. `CHG-21` retira código y documentación v1; no cambia la API v2. Si al ejecutar aparece la necesidad de un contrato nuevo, se detiene y se abre un `CHG-<n>` antes de tocar `src/frances/models/`, `contracts/` o `web/src/contracts/`.

## Review Focus

Del plan maestro v2: ítems 1 y 2 (toda ruta `/api/*` exige sesión y CSRF; las de admin, `require_admin`), 4 (el reinicio del worker no duplica el pipeline) y 7 (backup online con retención). Del subsistema:

1. `/srv/frances/.env` queda en `600 root:root`, `caddy.env` en `644 root:root` sin secretos, y ni el repo ni los ADRs ni los logs contienen valores de claves o tokens. Test/evidencia: GOL-02 `stat` + `git grep` + búsqueda en logs.
2. Solo Caddy publica puertos y los tres servicios Python no son root. Evidencia: GOL-01/GOL-03 `ss -ltnp` y `docker compose ps`; test de P08 `test_only_caddy_publishes_ports_and_app_is_non_root` sigue verde.
3. El primer backfill corre en el servidor con datos reales y sus logs no contienen texto del curso ni secretos. Evidencia: GOL-04 búsqueda en logs y ADR sin nombres.
4. El backup de una base WAL usa `sqlite3.Connection.backup()`, verifica la copia y una restauración de prueba deja `integrity_check = ok`. Evidencia: GOL-04 `frances backup run|list|restore`; test de P08 `test_backup_uses_online_backup_and_integrity_check` sigue verde.
5. La aceptación adapta las 13 casillas de LIVE-03 v1 y agrega las de cuentas, HTTPS, backup, reinicio y retiro de v1. Evidencia: ADR-014 firmado, sin nombres reales.
6. El FRB1, R2 y el Worker v1 desaparecen del código y de los workflows, pero `tests/fixtures/demo_state.sql` y `tests/fixtures/demo_audio/` siguen existiendo y los usa el demo v2. Test: CHG-21 `test_frb1_runtime_and_v1_ops_are_gone`, `test_demo_fixtures_and_helper_survive`.
7. El refresh token de Google se saca reutilizando LIVE-01 v1 (pasos 2–5 y 7), no se inventa y se comprueba en el servidor con `frances auth check`. Evidencia: GOL-02/GOL-03.
8. HTTPS de verdad: `http://` redirige a `https://`, el certificado lo emite Let's Encrypt, HSTS está presente y las cookies de sesión salen `HttpOnly; Secure; SameSite=Lax` con nombre `__Host-`. Evidencia: GOL-03 y casilla 16 de GOL-05.
9. El firewall se abre en las dos capas (Security List/NSG de Oracle y firewall del sistema) y SSH no queda abierto a `0.0.0.0/0`. Evidencia: GOL-01.
10. La instancia no sale del Always Free (hasta 4 OCPU, 24 GB y 200 GB), el disco queda por debajo del 80 % y no hay OOM. Evidencia: GOL-05 casilla 18.

### Task GOL-01: Instancia Oracle ARM, red, puertos 80/443 y DNS del dominio

Deps: [SRV-13, SRV-14]

**Files:**
- Create: `docs/decisions/ADR-010-golive-instancia-oracle.md`

Tarea humana (`human: true`, spec §12.2). Un agente puede dejar el borrador del ADR con las casillas vacías y la lista de comandos; el dueño ejecuta en la consola de Oracle y firma.

**Interfaces:**
- Consumes: `infra/compose.yaml` (SRV-13) — los únicos puertos publicados son 80/443 TCP y 443/UDP; `infra/README.md` (SRV-13).
- Produces: una instancia `aarch64` con IP pública, Security List/NSG y firewall del sistema abiertos solo en 80/443 (y SSH restringido), un registro DNS `A` (y opcional `AAAA`) que resuelve al dominio, y `ADR-010-golive-instancia-oracle.md` firmado. No produce código.

Checklist:

- [ ] **1. Crear la instancia.** Oracle Cloud → Compute → Instances → Create. Región más cercana disponible (anotarla en el ADR). Shape `VM.Standard.A1.Flex` con 4 OCPU y 24 GB de RAM (o el máximo que permita Always Free en esa cuenta), imagen **Ubuntu 24.04 LTS aarch64**, volumen de arranque de hasta 200 GB, IP pública IPv4 y una clave SSH propia. Si la región no tiene capacidad A1, reintentar más tarde u otra Availability Domain; **no** pasar a una forma de pago sin aprobación del dueño. Anotar el OCID de la instancia en el gestor del dueño, no en el repo.
- [ ] **2. Security List / NSG.** En la VCN de la instancia, reglas de ingreso: TCP 80 desde `0.0.0.0/0`, TCP 443 desde `0.0.0.0/0`, UDP 443 desde `0.0.0.0/0`. SSH 22 solo desde la IP pública del dueño (o deshabilitado y acceso por consola). Egreso: todo. No abrir 8000, 5432, 6379 ni ningún otro puerto.
- [ ] **3. Firewall del sistema.** Entrar por SSH y comprobar la capa local (`sudo ufw status` o `sudo iptables -L INPUT -n --line-numbers`). Abrir 80/tcp, 443/tcp y 443/udp en la capa activa y persistirlos (`sudo ufw allow 80/tcp`, `sudo ufw allow 443/tcp`, `sudo ufw allow 443/udp`, `sudo ufw enable`; o las reglas equivalentes de `iptables` + `netfilter-persistent`). Confirmar que SSH sigue permitido.
- [ ] **4. Sistema base.** `sudo apt update && sudo apt upgrade -y`; `sudo timedatectl set-timezone America/Bogota`; `timedatectl` debe mostrar `America/Bogota`. Instalar `ca-certificates`, `curl`, `git`, `gnupg`, `sqlite3` y `tmux` (Docker se instala en GOL-03). No instalar nada que abra puertos.
- [ ] **5. DNS.** En el proveedor del dominio, crear un registro `A` `<dominio> → <IP pública>` (TTL 300) y, si se usa IPv6, un `AAAA`. Si el DNS pasa por Cloudflare, dejarlo en modo **DNS only** (nube gris): el proxy naranja impide el reto HTTP-01 de Let's Encrypt salvo configuración extra. Verificar desde fuera: `dig +short A <dominio> @1.1.1.1` devuelve la IP pública.
- [ ] **6. Puertos desde fuera.** Desde un equipo que no sea la instancia: `nc -vz <dominio> 80`, `nc -vz <dominio> 443`, `nc -vzu <dominio> 443` deben conectar. `nc -vz <dominio> 8000` (y 5432/6379) debe fallar. Antes de GOL-03 Caddy aún no responde HTTP; que el puerto acepte la conexión es suficiente.
- [ ] **7. SSH.** `ssh ubuntu@<dominio>` funciona con la clave; `ssh -o BatchMode=yes ubuntu@<dominio>` no pide contraseña. Un intento desde otra IP debe fallar. No se guarda la clave privada en el repo.
- [ ] **8. ADR.** Escribir `docs/decisions/ADR-010-golive-instancia-oracle.md` con: estado (`Aceptado`), fecha, región, shape, OCPU/RAM/disco, sistema operativo, si el dominio está en DNS only, y una tabla `# | comprobación | pass/fail | nota` con las casillas 1–7. No anotar IP, dominio, correo ni OCID reales: decir «valor en el gestor del dueño» o usar `<dominio>`.
- [ ] **9. Commit.** `git add docs/decisions/ADR-010-golive-instancia-oracle.md && git commit -m "docs(adr): instancia Oracle ARM, red y DNS del go-live [GOL-01]"`.

**Definition of Done:** ADR firmado; DNS resuelve; 80/443 TCP y 443/UDP conectan desde fuera; SSH restringido; el resto de puertos cerrado; la instancia está en `America/Bogota`; no hay recursos de pago.

**Review Focus:** el firewall está en las dos capas (Security List/NSG y sistema); SSH no está abierto a `0.0.0.0/0`; no se anotaron IP, dominio ni credenciales reales; no se abrió ningún puerto que no sea 80/443.
