# Frances Classroom v2 — Plan maestro (servidor propio + estudio guiado por IA)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Lee `AGENTS.md` antes de tomar una tarea.

**Goal:** Llevar Frances Classroom a un servidor propio (Oracle Cloud ARM) con cuentas, progreso por usuario, el pipeline v1 corriendo en un worker con programador interno y una capa de estudio generada por LLM, sin romper el demo sintético de GitHub Pages.

**Architecture:** `docker compose` con cuatro servicios (`caddy`, `api`, `worker`, `backup`) sobre `/srv/frances`. `api` es FastAPI (REST + SSE) con sesiones por cookie; `worker` es el mismo código con un programador y una cola de trabajos en SQLite (WAL); `backup` copia `state.db` y `blobs/` a Object Storage de Oracle. El pipeline v1 (`run_daily`, `run_reconcile`) se reusa tal cual como un trabajo de la cola.

**Tech Stack:** lo de v1 (plan maestro `2026-10-14-00-master-plan.md`) + FastAPI 0.162.0, Uvicorn 0.54.0, argon2-cffi 25.1.0, SQLite FTS5, Caddy 2.11.7, Docker Buildx + QEMU.

**Spec:** `docs/superpowers/specs/2026-11-02-frances-v2-servidor-design.md` (fuente de verdad). El spec v1 y el plan maestro v1 siguen vigentes en todo lo que este plan no reemplaza.

## Global Constraints v2

Heredan todas las Global Constraints del plan maestro v1. Se agregan o cambian:

- **Dependencias y ARM.** Toda dependencia nueva (Python o npm) va con versión exacta (R-01) y debe tener wheel `py3-none-any` o `manylinux` `aarch64` para CPython 3.12 (o ser binario de Debian dentro de la imagen). `scripts/check_aarch64_wheels.py` (SRV-01) lo verifica sobre `uv.lock` y corre en CI. espeak-ng, ffmpeg, tesseract y sqlite3 vienen de `apt` en la imagen.
- **Licencias.** Sigue la regla v1 (MIT/BSD/Apache-2.0/ISC/MPL-2.0 para código importado). Se acepta además **MIT-0** (más permisiva que MIT): es la licencia de `cffi`, que ya estaba en `uv.lock` por `cryptography` y ahora también la usa `argon2-cffi-bindings`.
- **Contraseñas.** Solo `argon2id` con `argon2.PasswordHasher()` de argon2-cffi y sus parámetros por defecto (perfil RFC 9106 de baja memoria). Nunca se loguea, devuelve ni guarda una contraseña en claro. Mínimo 12 caracteres, máximo 128, tras NFC.
- **Cookies.** Sesión en `__Host-frances_session` con `HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/`, sin `Domain`. CSRF en `__Host-frances_csrf` con `Secure`, `SameSite=Lax`, `Path=/`, legible por JS (sin `HttpOnly`). En la base solo se guarda `sha256` del token de sesión.
- **CSRF.** Toda petición `/api/*` que no sea `GET`, `HEAD` u `OPTIONS` exige: (a) si trae `Origin`, que sea igual a `FRANCES_PUBLIC_ORIGIN`; (b) con sesión, el header `X-CSRF-Token` igual al `csrf_token` de la sesión (comparación en tiempo constante); (c) sin sesión (login, aceptar invitación), `Origin` obligatorio. Falla → `403 {"code": "csrf"}`.
- **Autorización.** Toda ruta `/api/*` exige sesión salvo la lista cerrada `PUBLIC_ROUTES` (R-33). Las rutas `/api/admin/*` exigen `role == "admin"`. Un test enumera `app.routes` y falla si alguna ruta queda fuera de esta regla.
- **Tests sin red.** Sigue `pytest --disable-socket --allow-unix-socket`. La API se prueba con `fastapi.testclient.TestClient(app, base_url="https://testserver")` (en proceso, sin sockets TCP; `https` para que las cookies `Secure` viajen). Nunca se levanta uvicorn ni Docker en un test que no sea `@pytest.mark.heavy`. OneRouter, Azure y Object Storage se mockean (respx o `botocore.stub.Stubber`).
- **SQLite.** `state.db` en WAL, `busy_timeout = 5000`, `synchronous = NORMAL`, `foreign_keys = ON` (CHG-01). Un solo escritor a la vez por diseño (un `worker`, un proceso `api` con `--workers 1`). Ninguna transacción de escritura nueva puede envolver una llamada de red (la excepción v1 de SYN-04, R-26, se mantiene). `sqlite3.OperationalError: database is locked` en la API → `503 {"code": "busy"}`.
- **Secretos.** Solo en `/srv/frances/.env` (permisos `600`, dueño root, D12') y solo se leen en `frances.config` (`Settings.secret`, `Settings.optional_secret`, `resolve_state_db`). Ningún otro módulo toca `os.environ`. La lista completa está en «Variables de entorno».
- **Logs.** Uvicorn corre con `--no-access-log`; Caddy sin bloque `log` de acceso. Toda salida de la app pasa por `frances.log.redact()`. Nunca se loguean cookies, headers `Authorization`/`X-CSRF-Token`, tokens de invitación, contraseñas ni texto del curso. Los logs del servidor no son públicos, pero la regla se mantiene igual que en v1.
- **Contenedores.** Imágenes base fijadas por digest (`python:3.12-slim-bookworm@sha256:…`, `caddy:2.11.7@sha256:…`, `node:22-bookworm-slim@sha256:…`); el digest se resuelve al implementar con `docker buildx imagetools inspect`. Procesos Python con usuario no root `10001:10001`, `read_only: true` y `tmpfs: /tmp`. Solo `caddy` publica puertos (80, 443 TCP y 443 UDP).
- **Rendimiento.** Pantallas (salvo chat) < 300 ms en el servidor: los endpoints de lectura no llaman al LLM ni a la red; leen datos ya generados. Chat: primer token en < 30 s.
- **Timestamps y zona.** Igual que v1 (`norm_ts`, `format_ts`). El programador y los días de `study_plan` y `usage_daily` usan `America/Bogota`.
- **Datos reales.** Igual que v1: el repo sigue público y solo con fixtures sintéticos. Los datos reales viven solo en `/srv/frances/data` y en el bucket de backup.

## Review Focus v2

1. Una ruta nueva sin dependencia de auth quedaría pública. Test: SRV-04 `test_every_route_requires_auth_except_public_routes`.
2. `POST` autenticado sin `X-CSRF-Token`, o con `Origin` ajeno → 403, sin efectos. Test: SRV-04 `test_post_without_csrf_token_is_403_and_writes_nothing`.
3. Un enlace de invitación usado dos veces (o dos aceptaciones simultáneas) crea un solo usuario. Test: SRV-03 `test_invite_is_single_use_under_race`.
4. El worker se reinicia después de las 05:17: el pipeline del día corre una sola vez. Test: SRV-07 `test_restart_after_fire_does_not_enqueue_twice`.
5. Un trabajo que falla 5 veces queda `failed` con esperas 60/120/240/480 s entre intentos, y el admin lo ve y lo reintenta. Tests: SRV-05 `test_fifth_failure_marks_failed`, SRV-11 `test_retry_failed_job_from_admin`.
6. Descargar un archivo solo sirve blobs registrados en `attachments`/`audio`; ningún parámetro arma una ruta del disco. Test: SRV-08 `test_file_route_only_serves_registered_blobs`.
7. El backup de una base en WAL usa la API de backup en línea y verifica la copia; la retención borra lo de más de 14 días pero nunca la última copia. Tests: SRV-12 `test_backup_uses_online_backup_and_integrity_check`, `test_retention_keeps_14_days_and_latest`.
8. Una migración con trigger (`BEGIN … END;`) se aplica entera: el divisor de sentencias v1 cortaba en cada `;`. Test: CHG-01 `test_migration_with_trigger_body_applies`.

  caddy.env                 # FRANCES_DOMAIN, FRANCES_ACME_EMAIL, AZURE_SPEECH_REGION (644, sin secretos)

Comando único de despliegue (M1): `cd /srv/frances/app/infra && docker compose up -d --build`.

## API REST (`/api/*`)

Convenciones: JSON UTF-8; errores siempre `ApiError` con códigos `bad_request` (400, incluye validación), `unauthenticated` (401), `forbidden`/`csrf` (403), `not_found` (404), `conflict` (409), `rate_limited` (429), `busy` (503), `llm_unavailable` (503). ### SSE del chat

`POST /api/chat/threads/{id}/messages` responde `200 text/event-stream` con `fastapi.sse.EventSourceResponse` (FastAPI ≥ 0.135; no hace falta sse-starlette). El cliente usa `fetch` con lectura en streaming (EventSource no permite POST ni el header CSRF). Cada evento: `event: <kind>` y `data: <ChatEvent JSON>`. Orden: un `meta` (`message_id` del mensaje del usuario), cero o más `token`, uno o más `citation`, y `done` (`message_id` de la respuesta guardada) o `error` (`code` = `llm_unavailable` | `rate_limited` | `no_material`). Si FTS no recupera fragmentos, se emite `done` con `status = "no_material"` y el texto fijo «El material del curso no cubre esta pregunta.» sin llamar al LLM. En `done`, `code` lleva el estado del mensaje guardado cuando no es `ok`: `"no_material"` (precedido por un `token` con el texto fijo y sin `citation`) o `"partial"` (respuesta sin citas válidas del modelo; las `citation` son los 3 primeros fragmentos recuperados). Un `error` siempre cierra el flujo. Comentario `: ping` cada 15 s mientras el LLM piensa. Caddy no bufferiza (`flush_interval -1`).
